更新时间：2026-07-29

## 2. 已与当前实现核对的事实

- 已确认 FitMeet 的法定运营与协议主体全称为 `晤云科技（青岛）有限公司`，产品品牌为 `FitMeet`，联系邮箱为 `support@fitmeet.cn`；尚未提供的注册地址和客服电话没有被编造。
- FitMeet 注册流程要求确认年满 18 周岁，出生日期选择和资料确认均存在 18+ 限制。
- 当前开放手机号验证码和邮箱密码认证；密码服务端保存派生凭据，不应保存明文。
- App 使用系统照片选择器选择用户主动提交的照片，不读取通讯录，也没有跨应用广告跟踪声明。
- 定位能力把设备位置转换为约 1 公里模糊网格，支持拒绝定位后手动填写城市，不应保存或展示实时精确位置。
- 语音输入由用户主动开始，使用麦克风和 Apple Speech 框架完成语音转文字。
- Agent、需求卡、发布、候选搜索、邀请、好友、消息、群聊、举报和拉黑均存在明确的状态或服务端接口；写操作应等待用户确认和服务端回执。
- 当前基础设施涉及阿里云 RDS、OSS、短信、内容安全和阿里企业邮箱；Agent 通过服务端调用 DeepSeek；推送和系统语音能力涉及 Apple。
- App 已有“我的—注销账号”入口，并提供数据导出与整账号删除操作，不是仅停用账号。

## 3. App Store 前必须由运营确认

以下项目没有在公开页面中被虚构；未完成时应阻止公开发布相应能力：

1. **主体信息**：法定主体全称已经确认为“晤云科技（青岛）有限公司”。提交前仍须用营业执照交叉核对官网、协议、App Store Connect 卖方信息和备案主体，并补充经核验、依法应公开的联系地址；在地址未经核验前不得自行填写。
2. **邮件服务商**：公开政策已按实际配置披露阿里企业邮箱及其服务提供者阿里云计算有限公司。公开启用前仍需由运营留档实际购买合同、数据驻留、日志与退信保存期限，并确认 [阿里云官网隐私权政策](https://terms.alicdn.com/legal-agreement/terms/suit_bu1_ali_cloud/suit_bu1_ali_cloud201902141711_54837.html) 与 [阿里企业邮箱产品服务条款](https://terms.alicdn.com/legal-agreement/terms/b_end_product_protocol/20231121171207894/20231121171207894.html) 的当前版本。
3. **第三方处理清单**：核验阿里云实际地域和产品、DeepSeek API 数据使用与留存条款、Apple 推送和语音处理、以及是否真正启用 Sentry 或其他监测 SDK。未列明的 SDK 不得在 Release 配置中静默启用。
4. **数据保存矩阵**：由后端和运维给出每张生产表、对象存储、访问日志、审核记录、邮件日志、备份与灾备副本的真实保存和清除周期；建立自动清理任务并用测试证明。公开政策不能替代真实删除能力。
5. **整账号删除**：使用真实账号验证账号、邮箱凭据、照片、动态、评论、需求、关系、群聊成员、推送令牌和非必要日志的删除或匿名化结果；法律要求保留的数据应隔离并记录依据、期限和权限。
6. **权利请求 SLA**：指定隐私负责人和客服工单流程，确保 `support@fitmeet.cn` 可收信并能在原则上 15 个工作日内完成身份核验、分派、答复和留痕。
7. **跨境评估**：确认 Apple 系统服务及未来监测、登录、邮件服务是否构成个人信息出境；如构成，依法完成告知、单独同意和适用的数据出境程序。
8. **算法与生成式 AI**：由律师结合开放用户范围、舆论属性、社会动员能力、Agent 输出形态和实际模型调用，确认算法备案、安全评估、生成合成标识、投诉机制及其他备案要求。完成前不得用协议文字代替法定手续。
9. **内容治理**：确认举报、拉黑、申诉、未成年人误用、紧急风险和侵权通知均有真实的接收人、处理流程、权限隔离与审计记录。
10. **App Store 对齐**：App Store Connect Privacy Nutrition Label、系统权限用途说明、SDK Privacy Manifest、应用内政策链接和本政策的数据分类必须逐项一致。

## 4. 版本发布与留存流程

1. 当前正式内容放在 `lib/legal/terms-v1.tsx` 和 `lib/legal/privacy-v1.tsx`。现行路由与版本 1.0 快照共同引用这两份冻结源文件。
2. 发布新版本时不得直接覆写旧版本文件。新建对应版本源文件和固定快照路由，再把 `/terms` 或 `/privacy` 指向新版本。
3. 在 `/legal/versions` 中记录文件名、版本号、更新日期、生效日期、现行或失效状态以及固定快照链接。
4. 第三方供应商、SDK、处理目的、信息种类、跨境情况或启用条件发生变化时，先更新 `/privacy/third-parties`，再评估是否需要提升隐私政策版本并重新征得同意。
5. 构建发布包前执行 `pnpm test:legal`、`pnpm typecheck` 和 `pnpm build`，并检查站点地图包含现行政策、第三方清单、版本记录与所有固定快照。

当前仍需人工核验且不得虚构的字段：

- “晤云科技（青岛）有限公司”与营业执照、ICP备案主体及 App Store Connect 卖方信息的一致性；
- 营业执照或正式运营资料核验、依法应公开的联系地址；
- DeepSeek API 实际采购合同或控制台订单中的签约主体、数据处理地域与留存条款；
- Apple 服务、邮件服务和未来监测服务的实际启用状态与跨境影响。

## 5. 发布检查

- `/terms`、`/privacy`、`/privacy/third-parties` 和 `/legal/versions` 在生产域名可通过 HTTPS 直接访问，不依赖登录，不含占位、草案或失效链接。
- `/legal/versions/terms-1.0` 与 `/legal/versions/privacy-1.0` 可以直接访问，正文、版本号和生效日期与 1.0 发布记录一致。
- 手机宽度 320–430 px、桌面和超大字体下可以完整阅读目录、正文、版本、生效日和联系方式，不横向溢出。
- 登录页的协议勾选非默认选中，用户能在同一流程打开两份完整文档。
- 重大更新会提升版本号、更新日期和生效日期，并通过应用内显著方式提示；需要重新同意时保留同意版本和时间。
- 每次供应商、权限、处理目的或保存期限变化，都先更新数据清单和政策，再启用生产功能。
